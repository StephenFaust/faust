## 工具入参 Schema：实现 AbstractToolExecutor#getInputSchema（3 个执行器）

- 关键约束（已验证）：Spring AI 1.1.2 `MethodToolCallback#buildMethodArguments` 按 **Java 形参名** 取值 `toolInputArguments.get(parameter.getName())`；`ToolCallbackFactory#getMethod` 绑的是 `ToolExecutor.execute(T params, ToolContext)`，`javap` 确认编译产物 MethodParameters 为 `params` / `toolContext`。**因此 schema 必须把真实参数包在顶层 `params` 里**，否则模型输出扁平 JSON 会被解析成 null。
- `AbstractToolExecutor`：新增 `PARAMS` 常量、`textParamsSchema(description)`（文本型单参）与 `wrapWithParams(paramsSchema)`（包一层 params 并声明必填）。
- `DbToolExecutor`：`params` 为 string，描述写明只读 SELECT/WITH、禁写与 DDL、MAX_QUERY_ROWS=500、数据源 dbType。
- `SubAgentToolExecutor`：`params` 为 string，强调任务描述必须自包含（子 Agent 无父会话历史）。
- `HttpToolExecutor`：由 `HttpToolSchema` 动态生成——parameters 逐项展开（类型归一化 int→integer、bool→boolean…、enum、default、in 位置提示并入 description），requestBody.properties 与 parameters 平铺，嵌套 object/array 递归；**source=ENV/UCID 的参数在任意嵌套层级都过滤**（模型填了也会被覆盖，且防止伪造身份/凭证）。
- 顺带健壮性：`HttpToolExecutor.execute` 对 `params == null` 兜底成空 Map，避免模型漏传时 NPE。
- 验证：`mvn -o -q compile` 通过；用临时 main（已删除）实跑三个 executor 打印 schema，JSON 合法且嵌套过滤生效（`data.owner`(UCID) 已被剔除、`data.required` 只剩 name/age）。

## 工具入参 Schema 改为「扁平」（替代 params 包裹）
- 放弃 `MethodToolCallback`（按 Java 形参名反射取值，逼着 Schema 包一层 `params`），新增 `com.faust.agent.tools.ToolExecutorCallback`（实现框架的 `StateAwareToolCallback` 标记接口），在 `call(toolInput, ctx)` 里用 fastjson 把模型 JSON 解析成 `Map` 直接交给执行器。
- `StateAwareToolCallback` 这一步是硬要求：`AgentToolNode` 只对 `StateAwareToolCallback` / `FunctionToolCallback` / `MethodToolCallback` 往 ToolContext 补 `_AGENT_CONFIG_`、`_AGENT_STATE_`、`_AGENT_STATE_FOR_UPDATE_`（1.1.2.2 字节码确认），`AgentConstants.AGENT_CONFIG` 正是 `_AGENT_CONFIG_`，子 Agent 工具靠它取 RunnableConfig，用普通 ToolCallback 会 NPE。
- `ToolExecutor` 去泛型，统一 `String execute(Map<String,Object> args, ToolContext)`；`AbstractToolExecutor` 去泛型，新增 `textParamSchema(name, desc)`、`objectSchema(properties, required)`、`textArg(args, expectedKey)`（约定名优先，唯一字符串值兜底）、`getParamNames()`（供兼容解包判定）。
- 三个执行器：DB 参数名 `sql`、SUB_AGENT 参数名 `task`、HTTP 保持逐项平铺（env/ucid 仍按层级过滤）。
- `ToolCallbackFactory` 改用 `ToolDefinition.builder()` + `ToolExecutorCallback`，删除 `getMethod()` / 反射查找 / `ToolDefinitions`；subagent 仍用 `MessageToolCallResultConverter`。
- 兼容：模型若仍输出 `{"params":{...}}`，单 key 且工具未声明 `params` 时自动解包。
- 验证：`mvn -o -q compile` 通过；临时探针实跑确认三种 Schema 均无 `params` 包裹、扁平入参直达执行器、legacy 包裹可解、DB 缺参返回「缺少必填参数 sql」。
